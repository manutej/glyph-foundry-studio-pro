# Compounding map — Transcendental Art engines
Unit of work: one maker build (v3, Orphic, ...). Substrate: this project folder.

## Loop
Frame (read docs/ + corpus) -> Do (build in one DC) -> Review (conservation checks + verifier) -> CAPTURE (update docs/, registry atoms) -> Repeat.

## Durable anchors (source of truth)
1. docs/ - constitution, meta-prompt, plan, this map. Update every build.
2. The symbol registry inside the DC (data, not code): name + tradition + meaning + recipe term. Grows monotonically; portable to Orphic Maker.
3. The palette/chord module pattern: strings + grounds + chord() - reused verbatim across makers.

## Top 3 leverage investments
1. Chord algebra as a palette-agnostic rule (done in v3) - removes per-palette hand-tuning forever; pays back on first palette swap.
2. Symbol registry as data - removes re-research of correspondences; pays back when TAROT corpus lands (merge, don't rewrite).
3. The meta-prompt (docs/meta-prompt.md) - makes the Orphic Maker a fill-in-the-slots job, not a rethink; pays back at P1.

## Capture / retrieval / refresh
- Capture: after each build, 3-6 bullet atoms appended to the relevant doc (what held, what broke, what to reuse).
- Retrieval: docs/ read at the start of every session touching the makers.
- Refresh: when the TAROT folder or v2 source becomes readable, reconcile registry + craft assumptions and mark stale atoms.
